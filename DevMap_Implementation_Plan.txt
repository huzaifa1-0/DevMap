What is DevMap?
DevMap is a VS Code extension that silently watches your JavaScript, Node.js, and Express projects. Every
time you save a file, it parses your code into an Abstract Syntax Tree (AST), matches the syntax patterns
against a built-in curriculum map, and shows you exactly which topics you have covered — in both a sidebar
panel and a full web dashboard.

Phase 1
Scaffold the Extension
~2 hours · pure Node + VS Code setup
Goal
Get a working VS Code extension that activates, registers a command, and shows a notification. This is your
Hello World — don't skip it.
Steps
Install tools
Run: npm install -g yo generator-code — this gives you the official VS Code
extension generator.
Scaffold project
Run: yo code → choose TypeScript → name it devmap. This creates package.json,
extension.ts, tsconfig.json.
Understand
package.json
Look at 'contributes' (commands, views) and 'activationEvents'. This file IS your
extension's manifest.
Register a
command
In extension.ts, use vscode.commands.registerCommand('devmap.scan', ...) and
test it via F5 in VS Code.
Add your first view
Add a 'contributes.viewsContainers' and 'contributes.views' entry in package.json
for the sidebar slot.
Key files after Phase 1
 package.json — manifest, commands, view registrations
 src/extension.ts — activate() entry point
 tsconfig.json — TypeScript config (already generated)

Phase 2
File Watcher + AST Parser
~1 day · the core engine
Goal
Every time you save a .js or .ts file, parse it into an AST and walk the tree to find which syntax patterns are
present. This is the brain of DevMap.
Steps
Install parser
npm install @babel/parser @babel/traverse — gives you a full JS AST with every
node type labelled.
Hook onDidSave
In extension.ts: vscode.workspace.onDidSaveTextDocument(doc =>
scanFile(doc.uri.fsPath))
Parse to AST
Call babelParser.parse(code, {sourceType:'module', plugins:['typescript']}) —
returns a full AST object.
Walk the tree
Use @babel/traverse to visit node types. Each visitor function receives a node. Log
them first to understand the shape.
Scan workspace
On activation, also run vscode.workspace.findFiles('**/*.{js,ts}') to scan all existing
files, not just on-save ones.
Return findings
Return a Set of matched topic keys (e.g. 'async_await', 'arrow_fn') from each file
scan.

Phase 3
Curriculum Map (topics.json)
~3 hours · define what you want to learn
Goal
Build a structured JSON file that defines every topic across three tracks. This file is the source of truth — the
AST matcher reads from it, the sidebar renders from it, and the dashboard visualises it.
topics.json structure:
{ "tracks": [{ "id": "javascript", "label": "JavaScript Core",
"topics": [{ "id": "arrow_fn", "label": "Arrow functions",
"astPattern": "ArrowFunctionExpression", "docsUrl": "..." }] }] }

Phase 4
Sidebar TreeView Panel
~half day · VS Code provider pattern
Goal
Render your topic progress as a collapsible tree in the VS Code sidebar. Each track is a top-level node;
topics inside show a checkmark (covered) or a circle (not yet). Clicking a topic opens its MDN/Node docs
page.
Steps
Create
TopicProvider
Implement vscode.TreeDataProvider. Two methods required: getTreeItem() and
getChildren().
TopicItem class
Extend vscode.TreeItem. Set iconPath to a checkmark or circle based on covered
status. Add a command for click-to-docs.
Register the
provider
vscode.window.registerTreeDataProvider('devmap.topicsView', new
TopicProvider(store))
Wire to state store
When the AST scanner updates covered topics, call
provider._onDidChangeTreeData.fire() to refresh the sidebar.
Add status bar item
Show '✓ 12/45 topics' in the VS Code status bar using
vscode.window.createStatusBarItem — always visible at a glance.

Phase 5
Web Dashboard (WebviewPanel)
~half day · HTML inside VS Code
Goal
A rich HTML dashboard that opens in a VS Code tab. Shows progress bars per track, a topic grid with
covered/pending states, and a Chart.js bar chart. Data flows from your extension to the page via
postMessage.
Steps
Create
WebviewPanel
vscode.window.createWebviewPanel('devmap', 'DevMap',
vscode.ViewColumn.One, {enableScripts:true})
Send data via
message
panel.webview.postMessage({ type:'update', data: store.getState() }) — call this
after every scan.
Receive in HTML
window.addEventListener('message', e => { if(e.data.type==='update')
renderDashboard(e.data.data) })
Build the UI
Pure HTML/CSS/JS in a template string. Use Chart.js (loaded via CDN) for the
progress bar chart per track.
Topic grid
Render a CSS grid of topic pills — green background for covered, gray for pending.
Click opens docs URL.
Add a reset button
A 'Clear progress' button posts a message back to extension:
panel.webview.onDidReceiveMessage(msg => ...)
Tip: The webview is sandboxed. You cannot use Node APIs inside it — treat it like a browser page. All data must arrive
via postMessage from the extension side.
